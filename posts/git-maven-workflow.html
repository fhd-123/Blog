Git 与 Maven：我的版本协作与构建工作流

2026-02-18 · 傅浩东

好的工具链能让人专注在业务本身。分享我在几个项目里沉淀下来的 Git 与 Maven 使用习惯。

一、Git 分支模型

个人项目我用 main + 功能分支：每个需求开一个 feature/xxx 分支，自测通过后合并回 main。提交信息尽量「动词 + 内容」，例如 feat: 新增订单状态机、fix: 修复地址校验为空。

二、提交要小步、可回滚

避免一次性塞进几百行改动。小提交出问题容易定位，git revert 也干净。

三、Maven 依赖管理

统一在父 pom.xml 用 dependencyManagement 锁定版本，子模块不再写版本号，避免依赖冲突。对工具类、公共实体抽成独立模块，减少重复代码。

四、本地构建再推送

推送前先 mvn clean package 跑通编译与测试，别把编译不过的代码丢给别人。

工具是下限的保证——用顺了，协作成本会肉眼可见地降下来。
