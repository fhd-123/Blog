MySQL 慢 SQL 优化：我是如何用联合索引把查询砍掉 30%

2025-12-20 · 傅浩东

在「芒果记账」项目中，账单模块需要支持时间、消费类型、金额范围的多条件复合筛选，最初的查询平均耗时约 120ms，用户感知明显。下面是我的优化过程。

一、定位慢查询

先用 EXPLAIN 看执行计划，确认是否走了全表扫描、是否命中索引、rows 估算是否过大。多条件联合查询没有合适索引时，MySQL 只能逐行过滤。

二、设计复合索引

根据高频筛选字段的顺序建立复合索引（最左前缀原则），让范围查询字段尽量靠后。建好索引后，复杂查询平均耗时下降到约 80ms，性能提升约 30%。

三、QueryWrapper 动态封装

用 MyBatis-Plus 的 QueryWrapper 按前端传入条件动态拼接，只在有值时追加 eq / between / ge / le，既灵活又避免无效条件干扰索引命中。

QueryWrapper<Bill> qw = new QueryWrapper<>();
if (type != null) qw.eq("type", type);
if (start != null) qw.ge("create_time", start);
if (end != null) qw.le("create_time", end);
if (min != null) qw.ge("amount", min);
if (max != null) qw.le("amount", max);

四、小结

索引优化不是越多越好，要结合真实查询模式与写入成本权衡。先用 EXPLAIN 说话，再谈方案。
