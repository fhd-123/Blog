SpringBoot + Redis 缓存实战：从穿透到雪崩的防护

2026-01-12 · 傅浩东

在「江服快跑」和「家庭健康协同管理平台」两个项目中，我都用 Redis 缓存了用户、配送员信息以及家庭健康统计看板等热点数据。这里总结一下我对缓存设计的理解。

一、什么时候该加缓存

缓存不是银弹。判断标准很简单：读多写少、计算/查询成本高、对短暂非强一致可容忍。比如家庭健康统计看板，聚合计算开销大且用户不要求秒级实时，就非常适合「DB 计算 + Redis 带过期缓存」。

二、过期策略

  • 给每个热点 key 设置合理的 TTL，避免脏数据长期驻留。
  • 对统计类数据采用「接受短暂非强实时」的折中，降低 DB 聚合压力。

三、缓存穿透与雪崩

穿透：查询不存在的数据，请求直接打到 DB。对策是缓存空值或布隆过滤器。雪崩：大量 key 同时失效。对策是给 TTL 加随机抖动（如 base + random），错开失效时间。

四、小结

缓存的核心权衡是一致性、性能、复杂度。先想清楚业务是否容忍弱一致，再决定缓存粒度与过期策略，比盲目加 Redis 重要得多。
